# Polyblast Arena

An **original**, offline, single-player-vs-bots arena FPS for Windows, built in
**Godot 4.7 (GDScript)**. Stylized low-poly arena shooter in the spirit of the
classics. **v2 "BIG BOOM"**: real 3D assets (41 GLB models generated by the
Blender pipeline), 9 weapons with loadouts, 4 maps, 3 game modes, pickups +
armor, a 3D main menu with shop/loadout, and a persistent Points profile.
No third-party or copyrighted game assets anywhere.

## Engineering highlights

- A fixed-step, server-authoritative simulation runs movement, weapons,
  pickups, teams, rounds, scoring, bots, and hit detection at 60 Hz.
- The playable client is kept separate from the simulation and communicates
  through the same intent/state boundary an online transport can use later.
- A headless smoke suite exercises 80+ checks across combat, movement, bots,
  all four maps, navigation, modes, pickups, and scene wiring.
- A reproducible Blender toolchain generates the project's 41 original GLB
  assets instead of relying on a third-party asset pack.

## Play

- **Exported build:** run `export/polyblast_arena.exe` (build it once — see
  Export below; binaries are not committed).
- **From the editor:** open the project in Godot 4.7 and press Play.

In the menu pick a **mode** (Deathmatch / Team Deathmatch / Team Elimination),
a **map** (Foundry / Hangar Nine / Skyreach / Glacier Post), bots (1-8),
difficulty, score limit, and time limit. Set your 4-weapon **loadout**, buy
characters and weapon finishes in the **Armory** with Points earned in matches
(10 per frag, +25 per win).

### Controls

| Input | Action |
|---|---|
| WASD + mouse | Move / look (Quake-3 style: air-strafe & bunny-hop work — hold Space) |
| Space | Jump (hold for auto bunny-hop) |
| Ctrl | Crouch |
| Mouse 1 | Fire |
| 1-4 | Loadout weapon slots |
| 5 | Circuit Blade (melee, always carried) |
| Esc | Pause |

### Weapons (9)

Pulse Rifle (auto), Thumper (rockets — rocket jumps work), Scattergun,
Longshot (sniper), Viper (sidearm), Ion Splatter (energy), Nova Cannon
(heavy — best rocket-jump knockback), Circuit Blade (melee), Lobber
(arcing grenades).

### Modes & systems

- **Deathmatch** — first to the frag limit.
- **Team Deathmatch** — red vs blue team frags; no friendly fire (knockback
  still works — rocket-boost your allies).
- **Team Elimination** — one life per round, first team to 7 rounds.
- **Pickups** — health / armor / ammo (small, large, uber) respawn on timers;
  armor absorbs 2/3 of incoming damage. Jump pads launch you across the map.
- Time limit ends any match on the best score; falling into the void kills you
  (Skyreach!).

## Architecture — server-authoritative from day 1

Two layers that never bleed together:

- **`/sim` — SIM (authoritative):** all game state, movement resolution, hit
  detection, damage, pickups, teams, rounds, spawns, scoring; `/bots` brains
  run inside the SIM tick. Fixed 60 Hz tick. No input polling, no rendering.
- **`/client` — CLIENT (presentation):** input capture, camera, visuals/FX,
  HUD, menus, profile persistence, interpolation. Sends *intent dictionaries*
  to the SIM; reads state and a per-tick event queue back.

The offline game runs the SIM in-process as a local "server"; the human and
all bots are SIM entities under identical rules (bots literally submit the
same intent schema the human client does). Players are identified by ID
strings, never IPs.

### Headless SIM (dedicated-server seam)

```
# from the project (or the exported exe):
polyblast_arena.exe --headless -- --server --bots=5 --difficulty=1 --fraglimit=15 --map=1 --mode=1 --timelimit=300
godot --headless --path . res://scenes/server_main.tscn -- --server --bots=5
```

Runs a bots-only match with zero rendering, prints the kill log, exits when
the match ends. `--map=0..3`, `--mode=0..2` (DM/TDM/TE).

### Where Phase 2 (online) plugs in

`sim/sim_world.gd` is the entire authority surface: intents in via
`set_intent(id, dict)`, state out via `players` / `get_projectiles()` /
`get_pickup_state()` / `drain_events()`. A dedicated server is
`scenes/server_main.tscn` + an ENet peer. No SIM rewrite is needed.

## Asset pipeline

All 3D models are generated procedurally by our own scripts — no external
assets. `tools/asset_gen/style.py` is the shared Blender module (palette,
materials, primitives, GLB export, QA thumbnails); each `gen_*.py` builds one
asset family. Regenerate everything with:

```
powershell -File tools\asset_gen\run.ps1            # all families
powershell -File tools\asset_gen\run.ps1 -Only gen_weapons_a.py
```

The runner fails if any asset misses its triangle budget or fails to export.
Weapons: grip at origin, barrel +Y (Blender) → -Z Godot forward, `muzzle`
empty exported in the GLB. Characters expose a `pb_team` material that the
game retints per team.

## Verification

```
powershell -File dev\run_smoke.ps1 [-Godot <path to godot console exe>]
```

~90 headless checks: arena geometry ray-tests, navmesh coverage on all 4 maps,
movement (speed cap / jump / bunny-hop / jump pads), weapons (hitscan, rockets,
splash, knockback, rocket jump, melee reach, grenade gravity, carried-loadout
rules), pickups + armor absorption, TDM (team frags, friendly fire off), Team
Elimination round flow, time limit, kill-z, combat loop, bot roaming +
fighting, scene wiring. The runner fails on any GDScript error even when
Godot's exit code misses it.

## Export

Windows preset is committed (`export_presets.cfg`, embedded PCK). One-time:
install export templates for Godot 4.7, then:

```
godot --headless --path . --export-release "Windows Desktop" export/polyblast_arena.exe
```
