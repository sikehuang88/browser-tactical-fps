# 总体架构

> 依据《Web版战术竞技FPS 技术需求文档》第 4 章。

## 逻辑架构

```
浏览器客户端
  -> CDN：HTML、JavaScript、WASM、地图与音视频资源
  -> API 网关：认证、资料、大厅、战绩与配置
  -> 匹配服务：队列、分组、地区与技能分匹配
  -> 会话编排服务：创建、分配、回收专用游戏服务器
  -> 实时游戏服务器：权威模拟、命中判定、回合状态与反作弊校验
  -> 数据层：PostgreSQL、Redis、对象存储
  -> 可观测平台：日志、指标、链路、告警与审计
```

## 关键原则

1. **服务器权威**：客户端提交输入帧，不提交可信位置、命中或伤害结果。命中、伤害、经济、回合结果均由服务器决定。
2. **链路隔离**：实时对局链路（WebSocket/WebTransport）与普通业务 API（HTTPS/REST）完全隔离。
3. **版本化**：游戏配置、武器数值、地图、协议均有可追踪版本号，进入对局前完成版本协商。
4. **故障隔离**：单个对局实例故障不扩散；关键状态可审计、可回放、可由事件记录重建。

## 实时链路数据流

```
Client                          Server
  |  InputFrame (seq, buttons,   |
  |    look, buttons, ts)  ----->|  校验 -> 移动/射击状态机 (64 tick)
  |                              |  量化编码坐标 (厘米, int16)
  |   <-----  Snapshot (tick, 实体列表, 增量)
  |  Ack / Ping-Pong  <--->      |  RTT 采样
  |
  本地: 输入 -> 客户端预测 -> 服务器快照 -> 校正收敛
```

## 模块边界

| 模块 | 职责 | 禁止 |
|---|---|---|
| client/ | 渲染、输入采集、预测、快照插值、HUD | 不信任客户端数据 |
| server/ | 权威模拟、命中、经济、回合状态机 | 不暴露可复用长期密钥 |
| backend/ | 认证、资料、匹配、战绩、封禁、运营 | 不持有实时对局状态 |
| proto/ | 协议规范与线格式 | 不再高频状态中使用冗余 JSON |
