# 项目技术需求文档

版本：V1.0（需求评审稿）· 目标平台：桌面浏览器（Chrome / Edge / Firefox，Safari 为兼容目标）
游戏类型：5v5 第一人称竞技射击 / 爆破模式 · 技术定位：浏览器内直接运行的独立原创战术竞技 FPS

## 重要声明

1. 本项目仅借鉴 5v5 战术竞技 FPS 的**通用玩法**，不复制任何现有作品的商标、角色、地图、音频、美术、武器模型或其他受保护资产。
2. 本项目不依赖任何专有引擎源码或未公开接口。
3. 浏览器环境无法提供桌面客户端内核级反作弊，竞技安全依赖**服务器权威判定、数据分析、举报复核和账号治理**。

---

## 1. 需求优先级

- **P0**：首发必须实现，缺失则不可上线。
- **P1**：首发建议实现，可在风险可控时延期。
- **P2**：后续版本规划，不阻塞首发。

## 2. 首发范围

- 1 种核心模式：5v5 爆破。
- 2 张原创竞技地图；8~12 种原创武器（手枪/冲锋枪/步枪/狙击枪/投掷物）。
- 休闲匹配、私人房间、基础段位匹配。
- 第一人称游玩、死亡观战、计分板、文字聊天、快捷语音指令。
- 简体中文与英文；PC 桌面浏览器，键鼠输入。
- **暂不纳入**：移动端触控、Steam Workshop、皮肤交易/开箱/博彩、完整录像编辑器、单机剧情/开放世界/大逃杀、对原版资产的兼容。

## 3. 技术基线

| 层 | 选型 |
|---|---|
| Web 客户端 | TypeScript · Three.js（WebGPU 优先，WebGL 2 回退）· React（仅非实时界面）· Rapier WASM 物理（经验证可用）· Web Audio API |
| 实时服务器 | Linux 无界面进程 · 推荐 Rust（压测达标可 Go/C++）· **64 tick/s**（压测可切 32/128）· 单实例 10 人+观战 |
| 业务后端 | Go 或 TypeScript · PostgreSQL · Redis（可重建临时状态）· S3 对象存储 · CDN |
| 网络 | WebTransport/HTTP3 首选，WebSocket 回退 · 二进制编码，禁止高频 JSON · 版本协商 |
| 资产 | glTF/GLB · KTX2/Basis · Draco/Meshopt · Opus/AAC · IndexedDB 缓存（不存长期密钥） |

## 4. 架构原则

- 客户端提交**输入帧**，不提交可信位置/命中/伤害/经济。
- 实时链路与业务 API 隔离；单实例故障不扩散。
- 配置/武器/地图/协议全部版本化，进对局前协商。
- 关键状态变更可审计、可回放、可重建。

## 5. 核心功能需求（要点）

| 模块 | 编号 | 要点 |
|---|---|---|
| 账号 | AUTH-001~003 | 游客+正式账号；OAuth/OIDC 短期令牌可刷新吊销；资料校验 |
| 匹配 | MATCH-001~004 | 1~5 人组队；<80ms 地区优先、等待放宽；就绪确认；私人房间 |
| 对局 | GAME-001~005 | 服务器状态机驱动；经济系统；目标物安装/拆除；死亡后禁止有效输入 |
| 移动 | MOVE-001~004 | 服务器权威碰撞；客户端预测+校正；服务器碰撞数据不可改 |
| 武器 | WEAPON-001~006 | 配置版本化；服务器射线检测+≤200ms 回溯延迟补偿；部位/护甲/穿透 |
| 地图 | MAP-001~003 | 原创地图通过可达/视线/公平/碰撞/性能检查；逻辑与美术分层 |
| UI/音频 | UI-001~003 / SOCIAL-001~002 / AUDIO-001~002 | HUD 不泄露不可见信息；设置持久化；战绩以服务器为准；队伍语音 |
| 断线 | SESSION-001~003 | 限时重连恢复状态；断线占位/判负；观战防信息泄露 |

## 6. 网络验收指标

- 64 tick/s，单局 P99 tick < 12ms；快照 20~32Hz。
- 50ms RTT/0.5% 丢包：无持续回拉；100ms/2%：整局可完成；200ms：明确提示高延迟。
- 单玩家带宽：下行 ≤250Kbps，上行 ≤100Kbps（峰值保护）。
- 服务端**不接受**客户端上报的命中、伤害、资金或胜负。

## 7. 客户端性能指标

- 推荐配置 1080p 中画质 ≥60FPS（1% 低帧 ≥45）；最低配置 720p ≥45FPS。
- 主线程单帧 <16.7ms；首访 100Mbps 下 20s 进入大厅（缓存后 8s）。
- JS+WASM 压缩体积 ≤8MB；首场景必要资源 ≤35MB；单局内存 <1.5GB。
- 失焦/休眠恢复后重新同步服务器状态。

## 8. 渲染/资产/音频

- WebGPU 不可用自动回退 WebGL2 并说明禁用项；画质差异不得造成竞技信息优势（如完全移除烟雾）。
- 资源唯一 ID+哈希+版本+依赖+授权记录；只加载签名清单内资源。
- 分类混音、距离衰减；关键竞技音效在低音量/低性能下仍可辨识。

## 9. 安全与反作弊

- 全链路 TLS；鉴权/授权/输入校验/频率限制。
- 登录/匹配/购买/结算/举报/封禁/管理记录审计日志。
- 客户端代码、WASM、协议视为可分析，**不在客户端保存核心秘密**。
- 服务端校验速度/射速/弹药/装填/可见性/交互距离/状态转换。
- 异常检测：爆头率、反应时间、瞄准轨迹、穿墙命中、账号关联。
- 举报→证据留存→复核→处罚→申诉全流程；处罚允许误判复核。
- **边界**：不承诺检测所有外挂；不采集无关本地文件；以"不信任客户端"为主。

## 10. 数据与接口

- 核心实体：User / Profile / Party / Match / MatchPlayer / Rating / Penalty / GameConfig。
- 结算幂等键；段位/处罚/经济变更保留原因与前后值；Redis 仅可重建状态。
- 接口版本号+统一错误码+追踪 ID+幂等；分页稳定游标；不暴露内部细节。
- 管理接口独立权限域与网络策略。

## 11. 运维与可用性

- 核心服务月可用 99.9%；自动扩缩容+冷启动缓冲；故障池停止分配。
- 分环境灰度+可回滚；版本兼容检查；每日备份+恢复演练。
- 建议：战绩数据 RPO≤15min，核心服务 RTO≤60min。

## 12. 可观测性

- 每个请求/匹配/比赛唯一追踪 ID。
- 客户端：启动/加载/FPS/卡顿/内存/浏览器/GPU/网络质量/崩溃。
- 服务器：tick 耗时/实体数/消息量/带宽/GC/输入延迟/校正次数。
- 日志不含明文令牌、密码、支付信息、不必要个人数据。

## 13. 兼容与可访问性

- 支持最近两个主要版本 Chrome/Edge/Firefox（Firefox 允许 WS 回退）；Safari 明确提示而非白屏。
- 不支持 WebGL2/WASM/Pointer Lock/必要音频时，启动前阻止进对局并说明。
- 菜单键盘导航、焦点可见、文本缩放、色弱模式、字幕、可关震动/动态模糊。

## 14. 测试与发布阻断

- 单测/集成/网络/性能/安全/兼容六类测试。
- 对局专项：不同 RTT 命中一致性、贴墙/斜坡/边缘、射速/换弹/切枪竞争、断线重连信息权限、长时间内存。
- **发布阻断**：可复现 RCE/鉴权绕过/提权；客户端可控制命中/伤害/资金/胜负；结算重复发奖；性能不达标或大面积崩溃；无恢复路径的数据丢失。

## 15. 验收指标

端到端无人工干预完成全流程；≥1000 并发在线/100 场同时比赛 2h 稳定压测；64 tick P99<12ms；推荐配置 ≥60FPS；100ms/2% 丢包可整局；安全项通过；目标浏览器兼容；灰度/回滚/告警/备份手册齐备。

| 阶段 | 周期 | 内容 |

## 17. 主要风险与应对

1. 渲染性能差异大 → WebGPU 优先+回退+资源预算+画质检测+分层遥测。
2. WebSocket 队头阻塞 → WebTransport 优先，可靠/不可靠通道拆分。
3. 客户端易被分析修改 → 服务器权威+行为检测+人工复核。
4. 物理不一致 → 服务器权威+固定规则容差。
5. 首载过大 → 启动包预算+CDN+分区加载+版本化增量。
6. 玩法过度相似 → 全原创资产+上线前法律审查。

## 18. 最小团队与交付物

- 团队：技术负责人 1；Web3D 客户端 2~4；实时服务器 2；后端平台 1~2；技术美术 1~2；策划/关卡 2；3D 美术 3~6；音频 1；测试 2；DevOps 1。
- 交付物：可运行三端；地图碰撞/导航/性能报告；协议与接口文档；规则/武器/经济配置；测试与压测报告；部署/监控/备份/事故手册；安全报告与反作弊流程；依赖与授权清单。

## 19. 变更规则

- P0 变更记录原因/影响/负责人/目标版本/验收标准。
- 影响协议/存档/公平/安全的变更必须技术评审。
- 武器/经济/地图参数版本化；比赛开始后不热更核心规则。
- 新功能不得降低性能/安全/兼容底线（书面风险接受除外）；技术栈可替换但须通过同等验收。
